프로젝트 개요

퍼스널 컬러 진단, 뷰티 상품 탐색, 피드/커뮤니티, 리뷰, 결제, 푸시 알림을 포함한 Android 네이티브 서비스 앱입니다. 누적 200만 다운로드 규모의 운영 환경에서 주요 기능 개발과 유지보수를 맡았고, 사용자 흐름과 운영 안정성을 함께 점검하며 개선했습니다.

앱 설치 경로 열기

서비스 운영/구조

  • MVVM 기반 ViewModel/Repository 구조로 주요 화면의 상태와 데이터 흐름을 분리했습니다.
  • Navigation, ViewBinding/DataBinding, Coroutine/Flow를 활용해 화면 전환과 비동기 처리를 정리했습니다.
  • Retrofit/OkHttp 기반 API 연동과 예외 처리, 네트워크 응답 흐름을 운영 환경에 맞게 다뤘습니다.
  • Paging3, RemoteMediator, Room을 연결해 네트워크와 로컬 캐시를 하나의 피드 목록 흐름으로 구성했습니다.

피드/커뮤니티

  • Paging3와 RemoteMediator로 피드 데이터를 불러오고 Room 캐시로 목록 성능을 개선했습니다.
  • 피드 작성에서 이미지 선택, 크롭, 리사이즈, multipart 업로드, 태그/유저 자동완성 흐름을 연결했습니다.

  • Fragment와 ViewModel이 스테이지와 중간 결과를 중복 보유해 화면 전환 시 값이 어긋나는 문제를 원인으로 파악했습니다.
  • 결과 누적과 계산 책임을 ViewModel로 일원화하고 Fragment는 입력 전달과 렌더링만 담당하도록 재구성했습니다.
  • 단계 간 상태 정합성을 확보해 최종 결과가 누락되던 흐름을 줄이고 진단 완료율을 높였습니다.

  • DataStore로 로컬 사용자 선호 정보를 다루고, Firebase 인증 상태에 따라 시작 화면을 분기했습니다.

직관 기록

  • Firestore의 사용자별 logs 컬렉션에 직관 날짜, 상대 팀, 경기 결과를 저장했습니다.
  • callbackFlow로 Firestore snapshot listener를 Flow로 감싸 목록과 상세 기록을 실시간으로 관찰했습니다.
  • 기록 생성, 수정, 삭제를 같은 편집 화면에서 처리하고 저장 결과에 따라 화면을 복귀시켰습니다.

친구/랭킹

  • 닉네임 검색, 친구 요청 전송, 수락/거절, 친구 삭제 흐름을 Firestore 문서와 batch write로 구성했습니다.
  • 친구별 기록을 구독해 내 기록과 합친 뒤 전체 승률과 연도별 승률 랭킹을 계산했습니다.
  • WinRateCalculator로 승/패/무, 결정 경기 수, 승률 퍼센트를 분리 계산해 홈과 랭킹 화면에서 재사용했습니다.

실제 화면

홈 대시보드, 기록 목록, 친구, 랭킹, 마이페이지 탭을 실제 앱 캡처로 정리했습니다.

검증한 설계 선택

실시간 listener는 callbackFlow와 awaitClose로 감싸 구독 수명주기를 명시하고, 친구 관계 갱신은 batch write로 묶어 데이터 정합성을 우선했습니다. 승률 계산은 Firebase와 UI에 의존하지 않는 로직으로 분리해 홈과 랭킹에서 같은 규칙을 재사용할 수 있도록 설계했습니다.
